# Двойной туннель AmneziaWG

**Двойной туннель** — последний резерв для основного AWG-подключения. Роутер
подключается к внешнему WARP или AWG через WAN, а зашифрованные UDP-пакеты
основного AWG идут через внешний туннель к прежнему серверу. Сайты видят
выходной IP основного AWG-сервера. Используются уже настроенные пиры и ключи.

## Настройка и переключение

У основного профиля в блоке **«Резервные подключения» → «Двойной туннель»**
выберите включённое WARP- или AWG-подключение и сохраните настройки. Для
внешнего профиля можно включить **«Ожидать сбоя основного»**, чтобы он
запускался только по требованию. Если этот же профиль указан обычным резервом,
его обычное подключение проверяется раньше и при успехе даёт свой выходной IP.

Роутер сначала проверяет прямое подключение, пул резервных IP и обычные
резервные профили из настроек подключения и правил маршрутизации. Когда эти
варианты исчерпаны, роутер ждёт handshake внешнего туннеля через WAN и
переподключает основной AWG через него. Успех подтверждают свежий handshake
основного AWG и HTTPS-запрос через него к `https://1.1.1.1/cdn-cgi/trace`.
Панель показывает активный двойной туннель, наблюдаемый выходной IP и ошибки.

Рабочий двойной туннель сохраняется, пока обычный резерв недоступен. При
восстановлении обычного резерва он снова получает приоритет, а основной AWG
возобновляет попытки через WAN. Если двойной туннель сам теряет связь и
требует переподключения, основной AWG снова начинает попытки через WAN.
Переключение использует один экземпляр основного пира, поэтому отсутствует
конкуренция двух экземпляров за последний аутентифицированный адрес пира.
[WireGuard roaming](https://www.wireguard.com/#built-in-roaming)

## Условия работы

Схема помогает, когда прямой IP или UDP-порт AWG-сервера недоступен из сети
провайдера, а внешний туннель всё ещё может доставлять до него UDP. Сервер
должен быть доступен с выходного адреса внешнего туннеля. Блокировка выходного
IP основного AWG на стороне приложения сохранится.

`AllowedIPs` внешнего пира должны включать адрес основного AWG-сервера. У
внешнего интерфейса должен быть адрес соответствующего семейства. WARP-профиль,
генерируемый панелью, переносит IPv4. Для автоматической HTTPS-проверки
основному AWG также нужен рабочий выход в IPv4-интернет. Внешний туннель должен
работать напрямую через WAN, поскольку режим поддерживает два уровня.

## Маршрутизация на роутере

Роутер помечает UDP-сокет основного AWG через UAPI `fwmark` и устанавливает
отдельное правило маршрутизации до сервера через внешний интерфейс. Резервный
запрещающий маршрут останавливает помеченные пакеты при потере внешнего пути до
контролируемого переключения режима. Маршруты WAN сохраняются для прямых
попыток и для подключения внешнего туннеля. Трафик устройств и DNS продолжает
поступать в основной AWG по настроенным правилам.

MTU основного AWG уменьшается с учётом MTU внешнего туннеля, семейства IP и
накладных расходов AWG. Этот MTU учитывается в правилах TCP MSS. HTTPS-проверка
подтверждает передачу данных и выходной IP. Крупные UDP-пакеты и поведение после
сбоя внешнего туннеля следует проверять отдельно для конкретных профилей и
прошивки роутера.
