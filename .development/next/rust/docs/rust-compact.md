# Компактная сборка для Keenetic с Entware

Для самостоятельного Rust-сервера используется [отдельная сборка](rust-native.md).

Это первый этап переноса панели на Rust. Базовый пакет запускает существующий Go-сервис и содержит заранее сжатый интерфейс. Отдельные страницы загружаются с роутера при открытии раздела. Пакеты устанавливаются через `opkg`. Во время работы панели компиляторы и Cargo не нужны.

| Пакет | Что устанавливает |
| --- | --- |
| `nfqws2-strategy-compact` | Панель, общие ресурсы интерфейса и скрипты обслуживания |
| `nfqws2-strategy-runs` | Страницу прогонов. Entware также установит пакет стратегий той же версии |
| `nfqws2-strategy-blockcheck` | Страницу BlockCheck |
| `nfqws2-strategy-strategies` | Страницу стратегий и каталог восьми встроенных ручных профилей |
| `nfqws2-strategy-geo` | Страницу GeoSite/GeoIP и исполняемый Rust-парсер `nfqws2-geo` |

Исполнители прогонов, BlockCheck и автоматического подбора пока работают внутри Go-процесса. История прогонов читается с диска при первом обращении. Пользовательские стратегии хранятся в данных панели. Удаление опциональных пакетов через `opkg` сохраняет базы Geo, списки и историю. Для уже настроенных правил AWG используется прежний механизм раскрытия Geo-категорий.

## Сборка пакетов

На роутере команда `opkg print-architecture` показывает название архитектуры для индекса. На машине разработчика нужны Go из `go.mod`, Node.js с npm, Python 3, Rust с Cargo и оболочка sh. Ниже пример локальной сборки для AArch64 из корня проекта. Версия `0.1.0-1` обозначает тестовую ревизию пакетов.

```sh
npm --prefix frontend ci
rustup target add aarch64-unknown-linux-musl
sh scripts/build-compact.sh arm64 aarch64-3.10_kn 0.1.0-1
```

Для ARMv7 с аппаратным FPU используйте цель `armv7-unknown-linux-musleabihf` и первый аргумент `armv7`. Профили `mipsle` и `mips` собирают Go-базу с softfloat и три пакета интерфейса. Для включения Geo на MIPS сборщику `scripts/build-compact-feed.py` потребуется совместимый Linux-бинарник `nfqws2-geo` через `--geo`. Второй аргумент скрипта во всех случаях должен совпадать с архитектурой Entware конкретной модели.

Пакеты, контрольные суммы в индексе и тексты лицензий появятся в `dist/compact-feeds/<архитектура>/<версия>/`. Каждой новой раздаваемой сборке присваивайте отдельную ревизию. Панель принимает имена ресурсов из собственного манифеста, а пакеты привязаны к точной версии базы. Обычная полная сборка использует `scripts/build.sh`.

## Общий исполнитель Rust

В [самостоятельной Rust-сборке](rust-native.md) прогоны, BlockCheck, стратегии и Geo по умолчанию имеют отдельные исполняемые файлы. Это выгодно, когда на роутере нужен только один из этих разделов. Для установки нескольких разделов можно собрать репозиторий с одним исполняемым файлом для всех четырёх.

```sh
N2S_COMPACT_TOOLS=shared sh scripts/build-rust-compact.sh arm64 aarch64-3.10_kn 0.1.0-rust.6
```

Результат появится в `dist/rust-feeds/aarch64-3.10_kn/0.1.0-rust.6+shared/`. Укажите этот каталог в настройках репозитория Entware. Суффикс `+shared` различает варианты пакетов при одинаковой версии программы. Панель, трассировка и TGWS устанавливаются самостоятельно. При установке первого из четырёх разделов `opkg` докачает пакет `nfqws2-strategy-tools` той же версии. Остальным разделам понадобятся только их ресурсы и символьные ссылки. Для удаления раздела вместе с зависимостями, которые больше никому не нужны, используйте, например, `opkg --autoremove remove nfqws2-strategy-geo`. Если после обычного удаления всех четырёх пакетов исполнитель остался, его можно снять командой `opkg remove nfqws2-strategy-tools`.

Размеры для установки всех четырёх разделов взяты из локальных репозиториев `0.1.0-rust.6` и `0.1.0-rust.6+shared`, собранных из ревизии `2dd3809`. Загрузка измерена суммарным размером файлов IPK в байтах, установка — суммой полей `Installed-Size`. В общий вариант включён пакет `nfqws2-strategy-tools`. Панель, базы Geo, пользовательские данные и округление блоков файловой системой учитываются отдельно.

| Архитектура | Раздельно, загрузка | Раздельно, установка | Вместе, загрузка | Вместе, установка |
| --- | ---: | ---: | ---: | ---: |
| ARM64 | 1 249 993 | 2 312 511 | 614 041 | 1 138 979 |
| ARMv7 | 1 239 789 | 2 289 823 | 623 229 | 1 133 955 |
| MIPS little-endian | 1 390 131 | 3 134 575 | 694 954 | 1 515 899 |
| MIPS big-endian | 1 387 833 | 3 136 351 | 694 158 | 1 517 359 |

Для любого одного раздела экономнее отдельный пакет. Например, для Geo на ARM64 нужно скачать 205 377 байт и установить 374 135 байт, а с общим исполнителем — 596 888 и 1 122 516 байт соответственно. Для двух разделов отдельные пакеты экономнее, если один из них Geo. Для любой другой пары, а также для любых трёх или всех четырёх разделов экономнее общий исполнитель. Это верно по размеру загрузки и установки для всех архитектур в таблице.

Время обработки измеряли отдельно на Keenetic ARM64 при выборе профиля компиляции, на экспериментальных бинарниках с базой `0.1.0-rust.5`. После прогрева варианты запускали по очереди, по 21 разу каждый, включая старт процесса. Медиана перечисления 100 000 текстовых записей Geo составила 30,7 мс для отдельного и 30,9 мс для общего бинарника. Для компиляции 4 096 имён в двух группах стратегий результаты составили 104,0 и 107,3 мс. Уровень оптимизации `z` уменьшил общий ARM64-бинарник ещё на 54 152 байта, но поднял медианы до 49,1 и 167,6 мс. В профиле для роутеров сохранён уровень `s`.

На ARM64 в отдельном chroot проверена установка `0.1.0-rust.6+shared` через API панели. Все четыре страницы открылись из установленных пакетов, каждый штатный путь запустил нужную команду. Удаление одного раздела сохранило остальные. Команда `opkg --autoremove remove` для последнего раздела освободила место, занятое общим исполнителем.

## Установка из собственного репозитория

Разместите содержимое каталога сборки на своём сервере. Для Entware создайте `/opt/etc/opkg/n2s-compact.conf` со строкой `src/gz n2s-compact URL_КАТАЛОГА`, указав адрес каталога с `Packages.gz`. Для репозитория с обязательной проверкой подписи подпишите индекс своим доверенным ключом. Базовый пакет содержит установщик соответствующей версии.

```sh
opkg update
opkg install nfqws2-strategy-compact
N2S_PROFILE=compact sh /opt/lib/nfqws2-strategy/install.sh
opkg install nfqws2-strategy-geo
```

Это устанавливает базу и раздел Geo. Другие разделы можно добавить по имени из таблицы. Пример удаления раздела и обновления установленных компонентов после переключения на новую версию репозитория:

```sh
opkg remove nfqws2-strategy-geo
opkg update
sh /opt/lib/nfqws2-strategy/install.sh
```

Установщик определяет текущий профиль по исполняемому файлу. При обновлении он учитывает уже выбранные модули. Базы `.dat` занимают отдельное место в каталоге данных. Их можно удалить в разделе Geo перед удалением пакета, если эти файлы больше не нужны правилам маршрутизации.

## Проверки переноса

```sh
cargo test --workspace --locked --offline
cargo clippy --workspace --all-targets --locked --offline -- -D warnings
cargo build --release --workspace --locked --offline
npm --prefix frontend test
npm --prefix frontend run build:compact
NFQWS2_GEO_BIN="$PWD/target/release/nfqws2-geo" go test -tags n2s_compact ./internal/app ./internal/server ./internal/tools/store ./internal/services/strategy/core/catalog ./rust/geo/tests
python3 scripts/test-compact-feed.py
sh packaging/test-compact.sh
```

`rust/core` читает CPU, загрузку, uptime, память и swap из Linux procfs. Утилита `nfqws2-sysinfo [каталог-proc]` выдаёт один JSON-снимок. Процент CPU вычисляется по двум снимкам одного экземпляра сборщика, поэтому в разовой команде он равен `-1`. Утилита собирается отдельно от основной панели.

`rust/geo` реализует операции `list <geosite|geoip|text> <файл>` и `extract <тип> <файл> <категория> [лимит]`. Парсер читает файл через буфер, хранит счётчики категорий и выдаёт элементы выбранной категории в исходном порядке. В компактной панели он запускается только на время чтения. Для дифференциальных тестов на больших реальных базах используются локальные `dev/testdata/geosite.dat` и `dev/testdata/geoip.dat`, если они доступны.

## Измерения первой сборки

Бинарники панели для Linux ARM64, собранные из одних исходников с одинаковыми флагами Go, заняли 15 270 050 байт в полном профиле и 14 155 938 байт в компактном. Основную часть экономии дало предварительное сжатие общего интерфейса. Отдельные страницы прогонов, BlockCheck, стратегий и Geo занимают суммарно около 16 КиБ в сжатом виде. На ARM64 отдельный парсер Geo занимает ещё 368 720 байт. Базы данных в эти размеры не входят.

Для сравнения парсеров измерялось перечисление всех категорий одной базы с выводом JSON. На Windows x64 чередовались семь запусков каждого release-бинарника отдельным процессом после прогрева. Время в таблице — медиана с учётом старта процесса. Приведённый пик рабочего набора измерен с интервалом 1 мс.

| База | Размер файла | Go, время | Rust, время | Go, память | Rust, память |
| --- | ---: | ---: | ---: | ---: | ---: |
| GeoSite | 10 534 558 Б | 35,1 мс | 37,8 мс | 56,5 МБ | 4,7 МБ |
| GeoIP | 19 207 283 Б | 143,4 мс | 72,3 мс | 119,4 МБ | 4,6 МБ |

На Keenetic AArch64 проверены запуск статических Rust-бинарников, чтение procfs и обработка небольших GeoSite/GeoIP-файлов. Замеры времени и рабочего набора в таблице относятся к компьютеру разработчика.
